# Методические указания преподавателям по оцениванию зачёта

## 1. Назначение и структура зачёта

Зачёт включает два независимых блока:

- **Теоретический опрос** — до **10 баллов**.
- **Практическое задание** — до **10 баллов**.

Суммарно за зачёт студент может получить до **20 баллов**.

## 2. Теоретический блок (до 10 баллов)

### 2.1. Формирование билета

- Для каждого билета случайным образом выбираются **5 проверяемых модулей**.
- По каждому выбранному модулю студент получает **1 вопрос**.
- Итого: **5 вопросов** в одном билете.

### 2.2. Критерии оценивания ответа на один вопрос

Оценивание каждого вопроса основано на двух признаках:

- **Корректность** — показывает знание материала.
- **Полнота** — показывает глубину понимания и способность раскрыть тему.

Шкала:

- **0 баллов** — ответ некорректен.
- **до 1 балла** — ответ корректен, но неполон (снижение зависит от критичности пропусков).
- **до 2 баллов** — ответ корректен и полон (допускается вариативность внутри диапазона по степени полноты).

### 2.3. Итог по теоретическому блоку

- Максимум: `5 вопросов × 2 балла = 10 баллов`.
- Рекомендуется фиксировать балл по каждому вопросу отдельно и кратко указывать основание снижения.

## 3. Практический блок (до 10 баллов)

### 3.1. Общая модель оценивания

- Студент выполняет **одно практическое задание** из банка экзаменационных заданий.
- Каждое задание содержит **5 критериев приёмки**.
- Каждый критерий оценивается по шкале **0–2 балла**.
- Максимум за практический блок: `5 критериев × 2 балла = 10 баллов`.

### 3.2. Единая интерпретация баллов по каждому критерию (0–2)

- **0 баллов** — критерий не выполнен или выполнен некорректно.
- **1 балл** — критерий выполнен частично: результат есть, но неполный, с существенными пробелами в обосновании/воспроизводимости/качестве исполнения.
- **2 балла** — критерий выполнен полностью, корректно и проверяемо; артефакты консистентны и пригодны для проверки.

### 3.3. Проверяемые артефакты (в зависимости от выбранного задания)

Проверка должна опираться на предъявляемые студентом артефакты, указанные в задании:

- код/ноутбук/скрипты;
- технические отчёты (`BUG_REPORT.md`, `EDA_SUMMARY.md`, `HYPOTHESIS_REPORT.md`, `PERF_REPORT.md`, `RUNBOOK.md`, `ARCH_DECISION.md`, `API_CONTRACT.md` и др.);
- конфигурационные файлы (`Dockerfile`, `docker-compose.yml`, CI workflow и т.п.);
- подтверждающие материалы (логи, скриншоты, примеры ответов API, экспортированные таблицы/графики, `json/csv`-витрины).

### 3.4. Банк практических заданий и модули покрытия

1. **FastAPI + SQL-аналитика + отладка дефекта** — модули `M2, M3, M4, M7`.
2. **Мини-EDA + аналитическая витрина для API** — модули `M6, M5, M7`.
3. **Проверка гипотез и согласование выводов по выживаемости** — модули `M6, M5`.
4. **Сравнение пайплайнов предобработки и data-quality gate** — модули `M6, M5, M7, M4, M8`.
5. **Оптимизация вычислений и инженерная проверка качества** — модули `M5, M4`.
6. **Развертывание и базовый CI для учебного сервиса** — модули `M8, M7, M4, M3`.

## 4. Итоговая фиксация результатов зачёта

Рекомендуемый формат протокола по каждому студенту:

- Теория: 5 оценок по вопросам + сумма (до 10).
- Практика: 5 оценок по критериям + сумма (до 10).
- Итог зачёта: сумма двух блоков (до 20).
- Короткий комментарий преподавателя по сильным сторонам и зонам доработки.

## 5. Связь с общей системой оценивания дисциплины

- Баллы зачёта учитываются в общей балльно-рейтинговой системе дисциплины.
- Вклад зачёта в итоговый рейтинг: до **20 баллов** (`10` теория + `10` практика).
- Итоговая академическая оценка по дисциплине определяется по правилам и порогам, зафиксированным в `Exam/README.md`.
